# Codex IDE adapter contract

The Codex IDE extension does not install Agent Plugins. It can discover
standalone skills from a repository `.agents/skills/` surface and can use the
same Codex host MCP configuration as the desktop app and CLI.

## Canonical source

`skills/` is the only editable skill source. `materialize_ide_adapter.py`
copies each canonical skill, including `SKILL.md`, `references/`, `scripts/`,
`assets/`, and optional `agents/openai.yaml`, into `.agents/skills/`.

The generated surface is checked by exact byte hashes. Missing, stale, extra,
linked, reference, script, and metadata files are separate findings. Do not
repair a generated file by hand; regenerate it and rerun parity.

## Discovery boundary

IDE skill parity is source evidence, not host discovery evidence. Report
`codex_ide_adapter=PASS` only for generated source parity. Keep
`ide_skill_discovery`, installation, host readback, and live status independent
and `NOT_RUN` until the host has actually been exercised.

## Optional metadata

`agents/openai.yaml` is optional. Use it for display metadata, tool
dependencies, or an explicit `allow_implicit_invocation` policy when that
policy matters. Do not add metadata merely to populate a file. The adapter
copies it without rewriting it.

## MCP bridge

If a future portable package contains `mcp.json`, render a project-scoped
`.codex/config.toml.example` using host-supported MCP tables. Emit only command,
URL, allowed environment-variable names, or OAuth configuration references;
never embed a token, secret, credential-bearing header, or local user path.
The current Agent Plugins Author package is skills-only, so its MCP host gate
is explicitly not applicable and no MCP file is generated by default.

## AGENTS.md

The adapter does not generate `AGENTS.md`. Repository guidance is a separate
authoring decision and must remain minimal when justified.
